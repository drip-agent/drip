# M002: Agent Platform

**Vision:** DRIP gets a brain. Users chat with an AI agent at agent.drip.surf that researches people and companies via AgentCash-powered APIs, while a public discovery feed showcases autonomous agent findings — all in the same futuristic dark-theme aesthetic established in M001.

## Success Criteria

- A user visits agent.drip.surf, types "research Anthropic", and receives a structured company profile with real data sourced via StableEnrich through x402 payment
- Agent responses stream in real-time with visible typing/thinking indicators
- The discovery feed at agent.drip.surf/feed shows autonomous agent research entries generated without user interaction
- A new agent skill can be added by creating a single skill module file and registering it — no modifications to core agent logic, chat API, or UI required
- The agent communicates errors in-character ("Lost signal. Try again.") rather than exposing raw error states
- Wallet USDC balance is visible somewhere in the agent UI for operational awareness
- All agent.drip.surf pages maintain the same dark-theme + aqua-glow design language as drip.surf

## Key Risks / Unknowns

- **x402 in a web backend is uncharted** — AgentCash's `@x402/fetch` and `viem` are designed for Node.js CLI/MCP. Wrapping them in a Next.js API route with streaming LLM tool calls is novel. If x402 signing fails server-side or exceeds Vercel's function timeout, the entire product loop breaks.
- **Vercel KV + Cron for feed persistence** — No database or external storage exists in the codebase. Vercel Hobby limits cron to 2 jobs at once/day minimum. If KV setup or cron scheduling doesn't work reliably, the feed is dead.
- **LLM tool-calling reliability** — The agent must decide when to call StableEnrich, parse the x402-wrapped response, and format it coherently — all within a streaming response. Tool call loops, hallucinated tool args, and timeout cascades are real risks.

## Proof Strategy

- **x402 web backend** → retire in S01 by building the real chat with live StableEnrich calls through x402. Proven when a user types a research query and gets real enrichment data back in the streaming response.
- **KV + Cron persistence** → retire in S02 by building the real feed with Vercel KV storage and a cron-triggered autonomous agent run. Proven when the feed page renders entries that were generated by a cron job.
- **LLM tool-calling reliability** → retire in S01 by shipping the real tool-calling flow with step count limits and timeout configuration. Proven when the agent correctly routes research queries to StableEnrich tools without looping.

## Verification Classes

- Contract verification: verification shell scripts checking file existence, route responses, build success; AI SDK tool definition tests
- Integration verification: live x402 payment → StableEnrich → LLM → streaming response; cron endpoint → agent run → KV write → feed render
- Operational verification: error state handling (empty wallet, API down, rate limited), wallet balance display, graceful degradation
- UAT / human verification: agent voice consistency ("cool & mysterious"), response formatting quality, visual design consistency with M001

## Boundary Map

### S01

Produces:
- `middleware.ts` — subdomain router: `agent.drip.surf/*` rewrites to `/agent/*` routes, excludes `/_next`, `/api`, static files
- `lib/x402-client.ts` — `createX402Fetch()` function returning a payment-wrapped fetch using `X402_PRIVATE_KEY`, guarded with `import 'server-only'`
- `lib/skills/types.ts` — `SkillDefinition` interface: `{ id, name, description, systemPrompt, tools: Record<string, CoreTool> }`
- `lib/skills/registry.ts` — `registerSkill()` / `getSkills()` / `getSystemPrompt()` functions operating on a module-level registry
- `lib/skills/research.ts` — research skill module exporting a `SkillDefinition` with StableEnrich tools (company-lookup, person-enrich)
- `app/agent/layout.tsx` — agent-specific layout with adapted NavBar (agent links instead of landing page anchors), shared fonts/theme
- `app/agent/page.tsx` — chat UI built on `useChat` hook, streaming message display, input with send button
- `app/api/agent/chat/route.ts` — POST handler using `streamText` with registered skill tools, `maxSteps: 5`, `maxDuration: 60`

Consumes:
- M001 design system: `components/ui/*`, `components/layout/*`, `lib/utils.ts`, `app/globals.css` tokens

### S01 → S02

S02 consumes from S01:
- `lib/x402-client.ts` — reuses payment-wrapped fetch for autonomous StableEnrich calls in cron jobs
- `lib/skills/registry.ts` + `lib/skills/research.ts` — reuses skill tools for autonomous agent runs
- `app/agent/layout.tsx` — feed page shares agent layout

S02 produces:
- `lib/feed.ts` — `FeedEntry` type + `saveFeedEntry()` / `getFeedEntries()` functions wrapping Vercel KV operations
- `app/agent/feed/page.tsx` — feed page rendering `FeedEntry[]` as styled cards with ScrollReveal/FadeInStagger
- `app/api/cron/feed/route.ts` — GET handler authenticated via `CRON_SECRET`, runs autonomous research, persists to KV
- `vercel.json` — cron configuration: `{ "crons": [{ "path": "/api/cron/feed", "schedule": "0 8 * * *" }] }`

### S01 + S02 → S03

S03 consumes from S01 + S02:
- All existing agent surfaces (chat, feed, layout) for error hardening
- `lib/x402-client.ts` for wallet balance check endpoint
- `lib/skills/registry.ts` for modular skill registration proof

S03 produces:
- `lib/skills/social-trends.ts` — stub skill module (no live API calls, returns placeholder data) proving modularity
- `app/api/agent/wallet/route.ts` — GET endpoint returning wallet USDC balance (server-only)
- Wallet balance display component in agent layout
- Enhanced error handling across chat and feed: in-character error messages, empty wallet detection, API failure graceful degradation
- `scripts/verify-m002.sh` — milestone-level verification script
